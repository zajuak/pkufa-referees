# 北大足协裁判员管理

[在线使用](https://zajuak.github.io/pkufa-referees/) · [管理员入口](https://zajuak.github.io/pkufa-referees/#/admin)

首页保留每周裁判选派表。GitHub Pages 提供网站，用户自己的 Cloudflare Workers + D1 保存业务数据。

校内服务器独立副本：[裁判网站](http://10.129.83.25:8081/) · [管理员入口](http://10.129.83.25:8081/#/admin)。已复制云端当时的完整业务数据，之后由服务器本地 API、SQLite 数据库和独立登录配置运行，两处修改互不影响。此内网地址需在能访问该服务器的网络中使用。

- **公开访问**：每周赛程、裁判选派、赛事/周次/场地/姓名筛选、选派表和个人日历导出、管理办法。
- **裁判员查询**：无需密码，直接按姓名查询积分、工资、执裁与奖惩明细。
- **管理后台**：维护裁判档案、选派、工资标准和奖惩；Excel 导入导出；冲突检查、整日请假、工作总览、自动版本备份及恢复。

积分工资查询目前公开只读，管理员登录后才能修改数据、导入、恢复备份或管理账号。管理密码使用 PBKDF2 哈希，登录令牌有签名与过期时间。个人登录、查询密码重置与改密接口继续保留，前台暂不展示密码查询和账号开通入口；将 `PUBLIC_QUERIES` 改为 `false` 可在后端恢复原来的个人资料读取限制。

真实姓名积分工资数据、原始工资表、备份、账号密码和运行时 Secret **不在本仓库或 Git 历史内**。`data/example-store.json` 是没有业务记录的空示例。前端构建不包含初始业务数据。

## 自动时间补贴

按比赛日期及开赛时间自动识别：早场为 10:00 及以前开赛；晚场为 20:00 及以后开赛；非常规时间为周一至周五（不按节假日调休另作判断）。以北京时间日历日期为准，跨午夜仍按开赛日期和时间判断。

新增、修改时间、改期、Excel 导入及已有赛程读取时统一重算，旧手动时间标记与备注不再决定时间补贴。三类时间条件即使同时命中也只加一次 10 元；天气补贴仍手动登记，半决赛/决赛及临时替补补贴维持原规则。

## 选派时新增裁判

在选派搜索框输入新姓名，再从下拉框选择“新建并选派”。保存比赛时自动建立并关联裁判档案，姓名会出现在赛程和积分工资查询中。新档案初始为十一人制 E 级或五人制 C 级，基础积分、历史工资均为零；已有另一赛制档案时沿用同一身份并补齐当前赛制。

同名按去除空白后的姓名匹配，已有多个同名档案时必须明确选择。比赛与新档案一次保存，重复选派、时间冲突或版本过期导致保存失败时不会遗留新档案；取消表单也不创建档案。

## 学院回避与晋级

后台“球队与球衣”登记学院和绑定球队归属学院；“裁判员档案 → 回避设置”绑定裁判回避学院，支持联合球队和多学院回避。十一人制小组赛检查同赛事、赛季、组别的全部球队；淘汰赛检查当前双方及直接后续对阵的候选球队（包括胜者和负者分支）；分组排位赛按同组检查，单场排位赛只检查双方。五人制所有阶段仅检查本场双方。绑定资料不完整时明确提示；已知回避冲突会阻止选派保存，并在工作总览显示现有问题。

裁判回避绑定列表每页 30 人，可上一页、下一页或直接跳页，搜索后回到第一页，翻页保留未保存的勾选。首页选派表的“回避”列公开该场比赛需要回避的全部学院，未选派时也能查看；未绑定显示“待设置”，部分资料缺失显示“资料不全”。裁判个人页姓名下方展示其已保存的回避学院，未设置时留空；个人回避信息遵循裁判查询权限。

“积分榜与晋级”展示小组和分组排位赛积分、并列顺序和晋级关系；比赛编辑器可指定固定球队、小组名次或某场胜者/负者作为席位来源。须先建立完整小组赛程并录入结果，未结束时保留所有候选，不把当前领先队当成最终晋级队。赛果确定后收缩候选并更新下游球队及默认球衣颜色；上游变化会重查所有受影响的选派。已有下游赛果的参赛队改变时拒绝修改，需要先清除或更正下游赛果。分组成员改变会清除失效的并列排序。

可直接“读取积分榜并预览”：GitHub 版读取线上积分榜，校内版默认读取本机 `http://127.0.0.1:8080/api/records`（可通过服务器环境变量 `STANDINGS_API_URL` 配置），也可上传积分榜导出的 JSON。按赛事、赛季、阶段、组别和主客队唯一匹配，支持主客队方向转换和单场点球比分；预览确认后一次保存，已有相同赛果跳过，已有不同比分或重复对阵留待人工核对，多回合总分不写入单场。旧的已完成比赛仍允许暂不填写比分，不影响既有工资积分；没有比分的比赛不参与晋级计算。数据和学院绑定仍由两端各自独立保存。

## 自动周次与比赛阶段

比赛周次由日期自动生成：每个赛季的首场比赛所在周为第 1 周，以周四至下周三为一周。跨周按连续日历周计算，中间无比赛的周不跳过；不同赛事共用本赛季周次，不同赛季独立起算。新增、修改日期和 Excel 导入均自动重算，已有赛程读取时也按相同规则展示。周次不再手工填写。

## 球队球衣与附加助理裁判

后台“球队与球衣”按赛事绑定默认球衣颜色。比赛编辑时从主客队下拉框选队后自动填色，可为当场临时改色。修改默认绑定不追溯修改历史比赛；历史赛程中的队名会进入同赛事备选名单，但未确认的颜色不会被自动猜测。

工资表导出按赛事区分：新生杯无甲乙级，按三类岗位和常规／淘汰阶段统计 6 项；男足北大杯按甲乙级、岗位和阶段统计 12 项。已产生执裁记录但未填写甲乙级的男足北大杯比赛会提示补全后再导出，不归入乙级。

比赛中断后续赛更换裁判时，可在对应岗位勾选“中断后续赛更换裁判”，分别选派原场和续赛裁判，两人各计 0.5 场、各得一半积分和基础工资；时间、天气、阶段、临替等补贴按各自“本次实际补贴”金额登记，不再自动叠加。可分别填写实际执裁日期和时段，用于请假、冲突检查及核算；其他未换裁岗位仍计 1 场。导出和个人页均保留半场及两位小数积分。普通选派 Excel 重传保留已登记的续赛信息，改动该岗位时须在比赛设定中处理。

十一人制可在每场勾选“需要附加助理裁判（2 人）”，增加第一、第二附加助理岗位。两人均按助理裁判的基础工资、积分、赛事倍率和补贴核算，工资表的助理场次包含这两个岗位。重新上传旧版四岗位 Excel 不清除管理员配置的附加岗位。

首页仅在当前周次/筛选结果存在未取消的启用场次时显示两列附加助理；其他场次的附加岗位留空，未启用的周次保留原版表格。未选派岗位留空，五人制的第四官员栏显示“-”。

五人制女足北大杯固定使用“常规赛／排位赛／半决赛／决赛”四个阶段；历史常规阶段的内部标识保持兼容，积分和工资不因改名改变。十一人制继续使用原有阶段。

“排位赛”为独立阶段，按常规比赛积分核算，不套用淘汰赛 1.5 倍积分，也不触发半决赛/决赛专属补贴。Excel 中的“排位赛／排名赛／名次赛”会识别为该阶段。

半决赛额外补贴：主裁、助理和附加助理各 10 元，第四官员 5 元；决赛分别为 20 元和 10 元。五人制第一、第二裁判对应普通岗位，第三裁判对应低档补贴。选择准确比赛阶段后自动计入工资，无须重复登记奖惩；普通“淘汰赛”不自动视为半决赛或决赛。

## 开发与构建

Node.js >= 22.13，建议 Node 24：

```sh
npm ci
npm test
VITE_GITHUB_PAGES=true VITE_BASE_PATH=/pkufa-referees/ VITE_API_BASE=https://pkufa-referees-api.junkaizhao404.workers.dev npm run build:pages
npm run build:api
```

Pages 使用 HashRouter，刷新个人查询和后台链接仍然可用。静态文件全部保留项目路径前缀。

推送 `main` 后 GitHub Actions 自动测试、构建和发布 Pages。前端不需要数据库或登录 Secret。

后端代码在 `worker/github.mjs`，配置在 `cloudflare/wrangler.jsonc`，SQL 迁移在 `drizzle/`。使用自己的 Cloudflare 账号发布：

```sh
npm run build:api
npx wrangler d1 migrations apply pkufa-referees --remote --config cloudflare/wrangler.jsonc
npx wrangler deploy --config cloudflare/wrangler.jsonc
```

生产 Worker 需配置 Secret：`ADMIN_PASSWORD_HASH`（格式见 `worker/auth.mjs` 的 `passwordHash`）与 `SESSION_SECRET`。不要将 Secret 写入仓库、前端环境变量或 URL。首次管理员密码由部署者保管。管理员密码作为生产 Secret 配置，不写入本仓库。个人查询账号接口保留供后续需要时恢复。

上线数据库已导入原站数据。后续部署不清空或覆盖云端记录；空库首次读取才使用示例种子。每次业务保存原子新增快照，旧版本提交返回 409。恢复前后完整版本均保留，账号凭据独立保存，恢复业务备份不会还原旧密码。

`tests/` 使用合成数据验证积分、Excel 导出、公开查询与原有个人权限、密码签名、过期、重置撤销和登录限流；真实原始表格的核对测试保留在部署者本机，不上传本仓库。

## 校内服务器部署

根路径版本使用独立输出目录，不改 GitHub Pages 构建：

```sh
VITE_GITHUB_PAGES=true VITE_BASE_PATH=/ VITE_API_BASE= npm run build:campus
npm run build:campus-server
```

服务器上使用 `/opt/pkufa-referees/releases/<版本>/` 保存 `campus-dist/` 和 `campus-server/campus.mjs`，`current` 链接指向当前版本；独立 Node 24 运行时位于 `/opt/pkufa-referees/runtime/`。`deploy/pkufa-referees.service` 提供开机启动和失败重启，监听 8081，不占用现有积分榜的 8080。`/health` 返回 `dataMode: independent` 和网站发布版本。

独立业务库为 `/var/lib/pkufa-referees/referees.sqlite`（包含每次保存的完整历史快照）；只在空库首次启动时读取 `/var/lib/pkufa-referees/initial-copy.json`，以后更新或重启不重新导入、不覆盖本地修改。初始副本包含赛程、选派、裁判档案、积分工资、奖惩、请假、球衣绑定、管理办法及工资标准，导出文件和数据库不进入源码仓库或静态目录。历史版本从这次复制的版本起独立积累，旧云端历史仍保留在原站。

`/etc/pkufa-referees.env` 保存仅该服务器使用的 `ADMIN_PASSWORD_HASH` 和随机 `SESSION_SECRET`，权限为 root 0600；不复用云端会话密钥，不自动复制查询账号凭据。管理员初始口令沿用已有口令，裁判员仍按姓名公开查询。备份或迁移时需保留业务库（通过 SQLite 备份或停服后复制）和登录配置。更新后通过 `systemctl restart pkufa-referees` 生效，回退时应选择支持独立数据库的旧版本再重启，不能切回会写云端的共享版本。

独立前端只请求同源 `/api`，服务端不转发请求到云端；云端 `ALLOWED_ORIGIN` 仅允许原 GitHub Pages，防止旧服务器页面误写云端。
